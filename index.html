Option 1: Single Sign-On (SSO)

Users log in with the university credentials they already have. No separate Dimensions password.

Recommended
1. How it Works

Dimensions authenticates against your identity provider via SAML 2.0. Users enter their institutional email, are redirected to your campus login screen, and return to Dimensions signed in.

2. Best Suited For

Universities, research institutions, and large organizations with an existing Identity Provider (IdP) or federation membership (InCommon, UK Federation, SURFconext, eduGAIN).

3. End-User Flow

1. Enter institutional email → 2. Redirected to campus login portal → 3. Land back in Dimensions authenticated with personal preferences preserved.

Don't know these parameters? Send this pre-filled draft to your IT team:

Have These Ready Before Opening the Form

  • ✓ Entity ID or IdP Metadata XML: Federation members provide Entity ID; direct SAML users email metadata to support@dimensions.ai.
  • ✓ Email Domain(s): All primary domains and subdomains (e.g. university.ac.uk, staff.university.ac.uk).
  • ✓ IT Identity Contact: Name and email address of your network/identity administrator.
  • ✓ Test Account (Optional): Helpful for validating the SSO connection end-to-end.

Option 2: IP Range & Proxy Whitelist

Anyone on your registered network gets in automatically with no login or personal account needed.

1. How it Works

Dimensions validates the user's public IP against your registered campus subnets. Off-site users connect via your institutional VPN first.

2. Best Suited For

Universities and research institutes with high on-site foot traffic, walk-in library patrons, and centralized static IP ranges.

3. End-User Flow

1. Visit Dimensions from a registered IP → 2. Access granted immediately with full institutional entitlements → 3. If off-site, connect via VPN first.

Critical Proxy Architecture Rule

An optional proxy (such as EZProxy or OpenAthens) works with IP range only. Never combine a proxy configuration with Single Sign-On (SSO) or VPN routing.

Have These Ready Before Opening the Form

  • ✓All institutional IP ranges covering all physical campuses (one per line).
  • ✓Network contact name and email address.
  • ✓Confirmation of whether your users have institutional VPN access.
  • ✓If using a proxy: Proxy type, Fully Proxied Dimensions URL, and Proxy server IP.

Option 3: Email Domain Whitelisting

Anyone with an institutional email address can self-register. Zero IT configuration required.

1. How it Works

We whitelist your domain suffix. Any researcher registering with that domain gets automatic access and revalidates periodically.

2. Best Suited For

Smaller organizations, funders, and distributed teams with low IT overhead or no central Identity Provider.

3. End-User Flow

1. Create account with institutional email → 2. Click one-time verification email → 3. Log in, and revalidate periodically.

Have These Ready

All institutional email domains and subdomains to whitelist (e.g. uni.edu, med.uni.edu, alumni.uni.edu). Both staff and student domains should be listed.

Option 4: Named Accounts

Individual seats created for you by Digital Science. As Champion, you approve future requests.

1. How it Works

You provide a user list spreadsheet. Digital Science provisions individual seats and triggers activation emails to each recipient.

2. Best Suited For

Limited-seat subscriptions, project teams, departmental research units, funders with specific user groups, and pilot programs.

3. End-User Flow

1. Champion provides names and emails → 2. User receives activation email → 3. User sets password and logs in at dimensions.ai.

Notice for Symplectic Elements & Grant Tracker Clients

If your institution uses Symplectic Elements or Grant Tracker, your setup is managed end-to-end by your dedicated Implementation Manager. Do not submit this form or request a key through this portal.

CRIS API vs Analytics API

The CRIS API is architected specifically for syncing publication records into Institutional Repositories and CRIS/RIMS platforms. It supports automated polling of publication metadata, whereas the Analytics API is designed for ad-hoc analytical queries in Python or R.

Three Supported Pathways

  • Pathway A (Homegrown CRIS): Standard automated request.
  • Pathway B (Commercial CRIS — Pure, Converis): Vendor agreement must be confirmed with Digital Science prior to key request.
  • Pathway C (Direct Querying): Bulk harvesting or data warehousing requires prior DS written approval.

Key Activation Protocol (Crucial Sequence)

1. Register Account Create an account at cris-api.dimensions.ai. We strongly recommend using a generic institutional address (e.g. cris@org.ac.uk).
2. Log In Once Required: You must log in at least once. The "Request API Key" button will not appear in the interface until your first successful login.
3. Submit & Retrieve Click "Request API Key" in the portal AND complete the form below. Keys appear in your portal account once approved (no notification email is sent).
